# SPRINT G, SEGURANCA (P0 + P1, ~1 dia)

## [ ] SEC-1 (P0) Credencial default "lideranca/lideranca" sempre ativa
- Arquivo: `server.py:37-38, 84` (e `render.yaml` nao seta `LIDERANCA_PASSWORD`)
- CWE-798. A conta lideranca e injetada em `_valid_credentials()` sempre que o gate de auth esta ligado, com senha default "lideranca". Qualquer um loga e ganha Dashboard executivo, `/api/smoke/run` (cria/move/deleta cards reais no Pipefy via SMOKE_PIPEFY_TOKEN) e `/reports/*`. Destrava SEC-2.
- Fix: so registrar a role se `os.environ.get("LIDERANCA_PASSWORD")` existir, sem fallback default. Documentar a env no render.yaml com `sync: false`.

## [ ] SEC-2 (P1) Token Pipefy vaza em log.html/output.xml servidos por /reports
- Arquivos: `resources/keywords/api_session.resource:48-71` (Create Dictionary Authorization=${token}), `server.py:345-359` (geracao), `server.py:2151-2159` (rota /reports gateada so pela role lideranca)
- CWE-532. RequestsLibrary loga os argumentos da keyword, o Bearer fica em claro nos artefatos do Robot em `results/`, servidos por `/reports/<file>`. A esterilizacao de `config/active.robot` nao cobre output.xml/log.html.
- Fix: adicionar `--removekeywords name:Criar Sessao Nomeada` (ou flatten) no cmd do Robot em server.py, E limpar/mascarar output.xml + log.html dentro de `_sterilize_active_robots()`. Cobrir com teste de regressao (grep por "Bearer" nos artefatos apos run mockada real).

## [ ] SEC-3 (P1) SSRF via base_url controlada pelo usuario
- Arquivos: `server.py:2393-2439` (/api/discover-pipes, reflete upstream_body 300 chars na linha 2438), `server.py:2534+` e `_generate_robot` (/api/run aceita base_url livre)
- CWE-918. O servidor faz request pra URL arbitraria do body, sem allowlist nem validacao de esquema. SSRF semi-cego contra rede interna do Render / metadata endpoints.
- Fix: validar base_url contra allowlist (`api.pipefy.com`, `app.pipefy.com`, host do Activepieces configurado) e rejeitar IP privado/loopback/link-local antes de qualquer request. Aplicar nos 2 pontos.

## [ ] SEC-4 (P2) Nenhum header de seguranca nas respostas Flask
- Arquivo: `server.py` (nao existe after_request com headers)
- CWE-693. Sem CSP, X-Frame-Options, X-Content-Type-Options, HSTS, Referrer-Policy. Tokens em localStorage (`pv-vault-v1`) tornam qualquer XSS um exfiltrador de credenciais.
- Fix: `@app.after_request` setando CSP (script-src 'self' + o que os inline scripts exigirem), X-Frame-Options DENY, nosniff, HSTS, Referrer-Policy.

## [ ] SEC-5 (P2) Container roda como root e imagem sem digest
- Arquivo: `Dockerfile:1, 10`
- CWE-250/CWE-1104. `FROM python:3.11-slim` sem SHA, sem USER.
- Fix: pinar `python:3.11-slim@sha256:...`, criar usuario nao-root e `USER app` antes do CMD. Junto: criar `.dockerignore` (.git, node_modules, .venv, tests, snapshots, *.md), ver CI-5.

## [ ] SEC-6 (P2) requirements.txt sem pinning
- Arquivos: `requirements.txt` (tudo >=), `requirements-dev.txt`
- Builds nao reprodutiveis, supply chain aberto. Bonus: `requests` e usado em server.py:2410 mas nao esta declarado (vem transitivo).
- Fix: pinar com `==`, declarar requests explicitamente.

## [ ] SEC-7 (P2) verify_ssl desligavel pelo cliente + env morta no render.yaml
- Arquivos: `server.py:261-268, 2423`, `render.yaml:13-14`
- CWE-295. `verify_ssl=false` do body desliga validacao TLS servidor->Pipefy. `VERIFY_SSL` no render.yaml nao e lida por nada (so existe DEFAULT_PIPEFY_VERIFY_SSL).
- Fix: forcar verificacao em producao salvo flag de dev explicita; remover a env morta.
