Perguntas frequentes
Por que minha run falha com PERMISSION_DENIED?

O token usado não tem permissão de leitura no pipe ou organização. Causas comuns:

  • Token sem permissão de leitura no pipe escolhido (limitação por usuário no Pipefy).
  • Você está rodando Batch com pipes de organizações diferentes. O backend filtra por env_id, mas se você forçar manualmente vai dar 401.
  • Token expirou. Ver pergunta de renovação abaixo.
Como renovo um token expirado (Pipefy ou iPaaS)?
  1. Faz login no Pipefy ou Activepieces na UI web
  2. Gera novo Personal Access Token (PAT)
  3. Volta pro Validator → ícone de engrenagem no topbar (Gerenciar Ambientes)
  4. Aba Pipefy ou iPaaS → Editar o ambiente → cola novo token → Salvar
  5. environments.json reflete imediato (volume mount, sem rebuild)

Alternativa rápida: edita direto config/environments.json no campo token.

O que é a "Decisão D" mencionada nos avisos?

Decisão arquitetural MVP Honesto: features cuja UI mentia foram removidas até o backend respeitar de verdade.

Por exemplo, dropdowns de pipe origem/destino no Single-env existiam mas não viajavam no payload. Em vez de manter UI fachada, foram removidos. Voltam quando o A+ for implementado (já feito pra Snapshot Gerar/Comparar e Batch).

Detalhes na documentação · Roadmap A+.

Onde ficam os arquivos gerados (snapshots, relatórios)?
  • snapshots/ · arquivos JSON de baseline (volume mount)
  • results/validations.json · último relatório Pipefy
  • results/ipaas_validations.json · último relatório iPaaS
  • results/log.html e report.html · saída padrão do Robot Framework (acessível via botão Log/Report na tela de Resultados)
Editei um arquivo e a mudança não aparece

Depende do arquivo:

  • Volume mount (config/, results/, snapshots/): reflete imediato. Faz Ctrl + F5 no browser pra forçar recarga dos assets.
  • Dentro da imagem (server.py, web/, resources/, tests/): precisa rebuild com docker-compose up --build -d.
A tela de Resultados ficou "morta" (filtros e diff não respondem)

Significa que o run abortou antes de gerar validations.json e o frontend caiu em estado de empty state. O backend agora grava um fallback com status: EXECUTION_FAILED e mensagem real (parseada do output.xml) com hint sugerindo a correção.

Se ainda assim os controles ficarem dead, abre F12 console e me passa o que aparece como [v2].

Quero rodar com um pipe que não está no preset

Caminhos:

  • Snapshot Gerar/Comparar: já permite, basta selecionar no dropdown Ambiente · Pipe ou Pipe atual.
  • Single ou Cross: ainda não, faz parte do roadmap A+. Workaround: edita o config/<env>.robot manualmente trocando os UUIDs e roda.
  • Batch: adiciona o pipe em config/batch_pipes.json com env_id correspondente. Lembrando que o backend roda todos do JSON filtrados por env, não respeita a checkbox da UI ainda.

Como reportar um bug

Pra cada bug, descreve nesse formato:

  1. Cenário: qual modo + preset (ex: "Cross-env · cross_fourd_hmg_x_fourd_stg")
  2. Ação: o que você fez (cliquei X, digitei Y, troquei dropdown Z)
  3. Esperado vs aconteceu: o que devia acontecer e o que aconteceu
  4. Print + console: tira print da tela (Win + Shift + S) e copia mensagens do F12 console que comecem com [v2]
ⓘ
Em vez de "não funciona" ou "tá quebrado", esses 4 itens reduzem o ciclo de fix em horas. Reproduzir é 80% do trabalho.
